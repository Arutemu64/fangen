# 🎭 FANGEN

> Парсер заявок [Cosplay2](https://cosplay2.ru/) → Excel и файлы для
> **Нижегородского фестиваля анимации и фантастики FAN FAN**.

[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](LICENSE)
[![Python 3.14](https://img.shields.io/badge/python-3.14-blue.svg)](.python-version)
[![Lint](https://github.com/arutemu64/fangen/actions/workflows/lint.yml/badge.svg)](https://github.com/arutemu64/fangen/actions/workflows/lint.yml)

`fangen` — консольная утилита, которая забирает данные заявок из API Cosplay2
в локальную базу SQLite, а затем превращает их в **Excel-таблицы** и
**упорядоченные папки с файлами** участников. Инструмент нужен организаторам
фестиваля, чтобы не собирать расписание, списки и медиафайлы вручную.

> ✨ Вдохновлено проектом
> [Cosplay2-Automation](https://github.com/Himura2la/Cosplay2-Automation).

## ✨ Возможности

- 📥 Загрузка расписания и всех заявок из Cosplay2 в локальную базу.
- 📊 Экспорт одобренных заявок в Excel: сводный лист + отдельный лист на раздел.
- 📝 Заполнение планов по шаблонам-заголовкам из первой строки таблицы.
- ⬇️ Скачивание медиафайлов заявок через [yt-dlp](https://github.com/yt-dlp/yt-dlp).
- 🗂 Раскладка скачанных файлов по папкам и именам через гибкий шаблон.

## 📋 Требования

- [uv](https://docs.astral.sh/uv/) — единственный поддерживаемый способ
  установки и запуска (Python 3.14 подтянется автоматически).
- Аккаунт Cosplay2 с доступом к API нужного события.

## 🚀 Установка

```bash
git clone https://github.com/arutemu64/fangen.git
cd fangen
uv sync
```

## ⚡ Быстрый старт

1. Скопируйте пример конфига и заполните его своими данными:

   ```bash
   cp config.dist.toml config.toml
   ```

   Как минимум укажите `event_name`, `api_key` и `api_secret`
   (см. [Настройки](#-настройки-configtoml)).

2. Загрузите заявки в локальную базу:

   ```bash
   uv run fangen make_db
   ```

3. Выгрузите данные в Excel:

   ```bash
   uv run fangen make_data
   ```

Готово — рядом появится файл `data_<дата>.xlsx` со всеми одобренными заявками.

## 🧭 Использование

Общий формат вызова:

```bash
uv run fangen [ОПЦИИ] КОМАНДА [АРГУМЕНТЫ]
```

Список всех команд и подсказки доступны через встроенную справку:

```bash
uv run fangen --help
uv run fangen КОМАНДА --help
```

### Глобальные опции

| Опция | Описание |
|-------|----------|
| `-c`, `--config PATH` | Путь к конфигу. По умолчанию — `config.toml` в текущем каталоге. |

## 🛠 Команды

### `make_db` — загрузка данных

Загружает расписание и данные всех заявок из Cosplay2 и сохраняет их в
локальной базе. Это первый шаг: остальные команды работают уже с локальной
базой, повторно к API не обращаясь.

```bash
uv run fangen make_db
```

### `make_data` — экспорт в Excel

Создаёт Excel-файл с данными всех **одобренных** заявок.

- На первом листе — **сводный список** заявок в порядке расписания.
- Каждый раздел выводится на отдельном листе.

```bash
uv run fangen make_data [ПУТЬ] [--csv]
```

- `ПУТЬ` — куда сохранить файл. По умолчанию создаётся снимок с меткой даты и
  времени, например `data_2026-08-11T1430.xlsx`. Такие снимки не перезаписывают
  друг друга и сортируются по имени в хронологическом порядке.
- `--csv` — дополнительно выгрузить данные в плоскую CSV-таблицу рядом с
  Excel-файлом (тот же путь с расширением `.csv`, например
  `data_2026-08-11T1430.csv`). CSV повторяет сводный лист одной таблицей: без
  оформления, пустые ячейки остаются пустыми, а несколько значений одного поля
  объединяются через `; `. Такой формат удобнее для последующих запросов к
  данным и генерации отчётов через ИИ — он без потерь читается инструментами
  вроде pandas, а пустые ячейки распознаются как отсутствие данных. Excel-файл
  при этом сохраняет оформление и остаётся удобным для чтения людьми.

### `make_plan` — заполнение плана по шаблонам

Заполняет Excel-файл на основе **шаблонов-заголовков** из первой строки.

```bash
uv run fangen make_plan [ПУТЬ]
```

- `ПУТЬ` — путь к файлу плана. По умолчанию `plan.xlsx`.
  Если файла нет — он будет создан.

> ⚠️ Каждый запуск полностью перезаписывает файл.

Заголовки работают как **шаблоны карточек Cosplay2**. Примеры:

- `{ФИО} из {Город}` → `Иванов Иван Иванович из Нижний Новгород`
- `{Персонаж}` при нескольких значениях →
  `['Аль-Хайтам', 'Дори', 'Дэхья', 'Кавех', ...]`

Дополнительные поля:

- `{info}` — информация об объекте (событие, раздел или заявка).
- `{n}` — сквозная нумерация заявок.

Словарь преобразований имён полей хранится в
[`dictionary.json`](#-словарь-замен-dictionaryjson).

### `download_files` — скачивание файлов

Скачивает файлы из заявок через **yt-dlp**.

```bash
uv run fangen download_files [ПАПКА]
```

- `ПАПКА` — куда складывать скачанные файлы. По умолчанию `./files`.
- Учитывает разрешённые расширения из конфига (`allowed_exts`).
- Скачивает файл повторно, если заявка была изменена.
- Создаёт `log.txt` с результатами:
  - **\[OK]** — файл скачан или уже есть;
  - **\[SKIP]** — пропущен по настройкам;
  - **\[FAIL]** — ошибка (нужно скачать вручную).

### `move_files` — раскладка файлов

Перемещает скачанные файлы по шаблону `filename_template`.

```bash
uv run fangen move_files [ОТКУДА] [КУДА]
```

- `ОТКУДА` — папка со скачанными файлами. По умолчанию `./files`.
- `КУДА` — папка для разложенных файлов. По умолчанию `./stage`.

Дополнительные поля шаблона:

- `{n}` — нумерация заявок (только в режиме сцены);
- `{info}` — название карточки из Cosplay2;
- `{value_title}` — название поля, из которого скачан файл.

Создаёт `log.txt` с результатами:

- **\[OK]** — файл перемещён или уже существует;
- **\[SKIP]** — пропущен по настройкам;
- **\[FAIL]** — исходный файл не найден.

## ⚙️ Настройки (`config.toml`)

После установки создайте `config.toml` (проще всего — скопировать
`config.dist.toml`). Ниже перечислены все параметры.

### 🔑 Основные

| Параметр     | Тип | Описание                                                                  |
|--------------|-----|---------------------------------------------------------------------------|
| `event_name` | str | ID события — текстовый субдомен фестиваля (например, `fanfan2025summer`). |
| `api_key`    | str | Ключ API Cosplay2.                                                        |
| `api_secret` | str | Секрет API Cosplay2.                                                       |
| `db_path`    | str | Путь к локальной базе данных (по умолчанию `./database.db`).              |
| `dict_path`  | str | Путь к словарю для замены полей (`./dictionary.json`).                    |

### 📊 Excel

| Параметр          | Тип | Описание                     |
|-------------------|-----|------------------------------|
| `max_cell_length` | int | Длина строки текста в Excel. |

### 📂 Загрузчик и сортировщик — общие

| Параметр       | Тип    | Описание                                                                      |
|----------------|--------|-------------------------------------------------------------------------------|
| `dry_run`      | bool   | Пробный запуск (файлы не скачиваются/не копируются, только создаётся лог).    |
| `skip_fields`  | \[str] | Названия полей заявок, которые пропускаются при скачивании/копировании.       |
| `allowed_exts` | \[str] | Список разрешённых расширений файлов (без точки).                             |

### 🗂 Сортировщик

| Параметр            | Тип  | Описание                                                                                                                                                                                                                                                               |
|---------------------|------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `max_title_length`  | int  | Максимальная длина названия карточки (`{title}`, `{info}`). ⚠️ Не путать с длиной самого файла.                                                                                                                                                                        |
| `filename_template` | str  | Шаблон имён файлов. Поддерживает подстановки.<br/> Примеры:<br/> Для сцены:<br/>`"{n} [{Начало выступления}] {title} №{card} {value_title}"` + режим сцены<br/>Собрать все файлы по папкам:<br/>`{topic_title}/{title}/{value_title}` + отключить режим сцены |
| `stage_mode`        | bool | Режим сцены:<br/>• `true` — копируются только сценические файлы (по расписанию);<br/>• `false` — копируются все файлы (включая внесценические).                                                                                                                     |

## 🔤 Словарь замен (`dictionary.json`)

Поля в шаблонах можно называть по-русски: `dictionary.json` сопоставляет
короткие ключи с возможными названиями полей из Cosplay2. Например, ключ
`title` срабатывает на поле `Название`, а `n` — на `N`, `№` или `Номер`.

## 🧑‍💻 Разработка

Проект использует `uv` для всего, а качество кода проверяется линтером и
типизатором:

```bash
uv run ruff check   # линтер
uv run ty check     # проверка типов
```

Те же проверки собраны в pre-commit и запускаются в CI на каждый push и
pull request.
